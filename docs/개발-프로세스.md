## 1. 브랜치

| 브랜치 | 용도 | 배포 |
|---|---|---|
| `dev` | 기본 브랜치. 모든 개발 커밋 | NAS dev 웹 (`npm run deploy:dev`) |
| `test` | 검수. `dev` 를 머지 | NAS test 웹 (`npm run deploy:test`) |
| `live` | 출시. `test` 를 머지 | 앱스토어·플레이스토어 빌드 |

- 머지 방향은 `dev → test → live` 한 방향이다. 역머지하지 않는다.
- 커밋 메시지 끝에 `Co-Authored-By:` / `Claude-Session:` 트레일러.
- `.env`(제미나이 API 키)는 절대 커밋하지 않는다.

## 2. NAS 웹 배포

NAS 웹 루트 `\\DS216PLUSII\web\ddukbaek2` 아래 단계 폴더에 프로젝트 이름(`package.json` 의 `name`) 폴더로 배포한다.

| 단계 | 배포 폴더 | 주소 |
|---|---|---|
| dev | `\\DS216PLUSII\web\ddukbaek2\dev\<name>` | `https://dev.ddukbaek2.com/<name>/` |
| test | `\\DS216PLUSII\web\ddukbaek2\test\<name>` | `https://test.ddukbaek2.com/<name>/` |

```bash
npm run build
npm run deploy:dev     # 또는 deploy:test
```

- `tools/deploy.cjs` 가 `build/web/version.json`(푸시된 커밋 해시·날짜)을 쓰고 배포 폴더와 **미러링**한다. (Windows robocopy /MIR, macOS rsync --delete)
- ⚠️ 배포 폴더를 통째로 비운 뒤 다시 복사하는 방식은 금지 — SMB 삭제 중 서버측 잠금으로 폴더가 접근 불가가 된 사고가 있었다. (파이프매니아, 2026-07-27)
- macOS 에서 NAS 가 안 보이면 Finder ⌘K → `smb://DS216PLUSII/web` 접속 후 재시도.

## 3. 작업 마무리 순서 (매 작업)

1. 커밋 → `git push origin dev`
2. `npm run build`
3. `npm run deploy:dev`
4. `.logs/claude-YYYY-MM-DD.log` 기록 (`[HH:MM 요청 → HH:MM 응답]`, 날짜당 1파일)

## 4. 검증 (헤드리스 크롬)

- 정적 서버로 프로젝트 루트(개발 소스) 또는 `build/web`(번들)을 연다.
- `puppeteer-core` 는 저장소에 넣지 않는다. (`npm install --no-save` 또는 작업 폴더 밖에서)
- 헤드리스 크롬은 한 번에 하나만, 캡처 후 같은 명령 안에서 종료한다.

## 5. 스토어 출시

`live` 브랜치에서 `README.md` 의 "스토어 빌드" 절차를 따른다. 버전은 `project-manifest.json` 에서 올린다.
